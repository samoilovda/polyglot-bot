# ТЗ: Wordbank — пошаговое выполнение

> **Статус:** черновик v0.2 (2026-10-31). Документ живой: конечная форма продукта ещё не определена.
> **Исполнитель:** ИИ-агент (Sonnet), этапы выполняются **строго по порядку**, один этап — одна сессия.
> **Исходная спека:** [`SPEC-wordbank-v0.1.md`](SPEC-wordbank-v0.1.md) — снимок замысла владельца, ссылки вида «§6.2» ведут туда.

## 0. Как пользоваться этим документом

### 0.1. Иерархия источников истины
1. **Свежие указания владельца в чате/issue** — главнее всего.
2. **`DECISIONS.md`** в репозитории `wordbank` — журнал принятых решений (появляется на этапе Э1).
3. **Этот ТЗ** — порядок работ, критерии приёмки, принятые по умолчанию решения.
4. **SPEC v0.1** — исходный замысел. Если ТЗ и SPEC расходятся, действует ТЗ, а расхождение должно быть записано в §2 «Отклонения от SPEC».

Изменения ТЗ — отдельным коммитом с записью в §9 «Журнал изменений». SPEC v0.1 **не редактируется** — это снимок; новая версия замысла = новый файл `SPEC-wordbank-v0.2.md`.

### 0.2. Правила для исполнителя (читать перед каждым этапом)
- Перед началом этапа прочитай: этот ТЗ целиком, `DECISIONS.md`, раздел SPEC, на который ссылается этап, и `docs/STATUS.md` (что сделано).
- Делай **только текущий этап**. Работу следующего этапа не начинай, даже если «почти рядом».
- Коммит после каждого логического шага; сообщения на английском, в стиле Conventional Commits (`feat(lexicon): …`).
- Тесты — pytest, **без сети** (сеть мокается; фикстуры — маленькие файлы в `tests/fixtures/`). Линт — `ruff check` и `ruff format --check`. CI должен быть зелёным в конце этапа.
- Если решение не описано ни здесь, ни в `DECISIONS.md` — выбери самое простое обратимое, запиши его в `DECISIONS.md` с пометкой `[агент, требует подтверждения]` и продолжай. **Исключение — инварианты §1: их нарушать нельзя, нужно остановиться и спросить.**
- **⏸ Точка проверки владельцем:** закончи этап, запиши результаты в `docs/STATUS.md`, сформулируй вопросы и **остановись**. Следующий этап не начинать до ответа.
- В конце каждого этапа обнови `docs/STATUS.md`: что сделано, как проверить вручную (команды), известные ограничения, что осталось.
- Никаких секретов в git. Новые переменные окружения сразу добавляй в `.env.example` с комментарием.

### 0.3. Шаблон отчёта в конце этапа (в `docs/STATUS.md`)
```
## Э<N> — <название> — <дата>

Проверка вручную: <команды>
Решения агента (см. DECISIONS.md): …
Ограничения / долги: …
```

## 2. Отклонения от SPEC v0.1 (приняты по умолчанию в этом ТЗ)

Это **предложения исполнителя ТЗ**. Они встроены в этапы, потому что снижают риск, но владелец может отменить любое; тогда агент делает по SPEC.

| # | Отклонение | Почему | Если владелец против |
|---|---|---|---|
| О1 | **SQLite (WAL)** по умолчанию вместо «Postgres, если есть». | Один пользователь, бэкап = копия файла, нет отдельного контейнера. Доступ через SQLAlchemy, так что переезд на Postgres — замена URL плюс прогон миграций. | Поставить `DATABASE_URL=postgresql+psycopg://…`, добавить сервис в compose. |
| О2 | **Словарь — отдельный файл `lexicon.db`** (только чтение), личные данные — в `wordbank.db`. Связь — по `entry_id` плюс «ключ стабильности» `(lang, headword, pos, ipa)`. | Пересборка словаря = собрать новый файл и атомарно подменить его (`rename`). Бэкапить надо только маленькую личную базу. Словарь можно собирать **не на ARM-сервере**, а локально или в CI (стриминг 2.9 ГБ gzip). | Одна база, как в SPEC. |
| О3 | **Telegram-бот захвата работает через long polling** (в `worker`), webhook — опционально. | Не нужен публичный домен и HTTPS, чтобы начать пользоваться. Домен понадобится только для Android вне дома и для Э12. | Сразу webhook (SPEC §4.3). |
| О4 | **Порядок этапов изменён:** Telegram-бот (самый дешёвый канал захвата) идёт раньше веба и Android; парсер CSV из таблицы делается уже в Э3 (нужен для отчёта о покрытии); бэкапы появляются в Э2, то есть раньше, чем реальные данные. | Ценность появляется раньше, а реальные данные не попадают в базу без бэкапа. | Порядок SPEC §11. |
| О5 | **Сначала английский (en-GB)**: все сценарии доводятся до готовности на английском. es / pt-BR / uz импортируются и проходят тесты детекции, но ручная полировка UX под них идёт после Э8. | Владелец прежде всего работает со словарём английских слов; таблица — английская. | Все языки одинаково с первого дня. |
| О6 | Добавлены поля **`gloss`** (короткое английское значение из Wiktionary) и **`translation_ru`** (из секции translations английского Wiktionary, если есть) в словарь; **`lookup_count`** и **`capture_count`** — в `items`. | Без LLM получаем смысл и русский перевод для поиска, карточек и Anki. Повторный захват того же слова — сильный сигнал «плохо помню» для приоритета в практике и публикациях. | Не импортировать эти поля. |
| О7 | Подсказки опечаток (`/suggest`) через **SymSpell** (`symspellpy`), построенный по заголовкам словаря при старте, а префиксный поиск — через индекс SQLite. | Наивное расстояние Левенштейна по ~1 млн заголовков слишком медленное для цели p95 < 100 мс. | Другая реализация с той же целью по скорости. |
| О8 | Частотность слов — пакет **`wordfreq`** (только для ранжирования в детекции и подсказках). | В kaikki частотностей нет, а §5.3 SPEC их требует. | Без частотности, ранжирование только по типу совпадения. |
| О9 | Сборка Android APK — в **GitHub Actions** (артефакт), а не локально. | В облачном окружении агента может не быть Android SDK; владелец скачивает APK из артефактов. | Локальная сборка. |

## 3. Предложения и дополнения (НЕ встроены в этапы, ждут решения владельца)

| # | Предложение | Комментарий |
|---|---|---|
| П1 | **Экспорт в `.apkg` с аудио** (через `genanki`) в дополнение к TSV. | TSV не переносит аудио. Карточки с записью из Commons или синтезом заметно полезнее. Дёшево: 1–2 часа в Э10. |
| П2 | **Разные варианты слова — разные элементы**, но с группировкой в UI (`increase` сущ./гл.). | SPEC §8 уже так делает для импорта, предлагаю то же правило для обычного захвата: если у слова несколько POS с разной IPA, при сохранении предлагать выбор. |
| П3 | **«Минимальные пары»** в практике (ship/sheep, full/fool) из `issue_tags=vowel`. | Требует данных о парах; можно генерировать без LLM, сравнивая IPA словаря на расстояние 1 фонему. |
| П4 | **Запись своего голоса** в карточке практики (MediaRecorder, хранится локально, сравнение «на слух» с эталоном). | Без автоматической оценки (это non-goal), просто «послушать себя рядом с эталоном». `origin=user_upload` в модели уже есть. |
| П5 | **Обратная связь из публикаций**: в посте канала не отмечать, какие слова «мои», но в личный бот присылать «сегодня в канале были твои слова: …» с кнопками Good/Again. | Превращает публикацию в повторение без отдельного захода в приложение. |
| П6 | **Захват с Mac/Linux через горячую клавишу** (macOS Shortcut / `xdotool`+`curl` с токеном `capture`): выделил слово где угодно → ⌘⇧W → сохранено, уведомление с IPA. | Ближе к опыту Android-меню, чем открытие веб-страницы. Скрипт на 20 строк, в `tools/`. |
| П7 | **Синхронизация таблицы Google в обе стороны** вместо одноразового импорта CSV. | Если владелец продолжит вести таблицу параллельно. Если нет — не нужно. |
| П8 | **Отдельный канал/тред** для «Words in context» вместо общего канала цитат. | Снимает вопрос приватности «какие слова я учу» и не размывает формат канала цитат. |
| П9 | **Не тратить LLM-вызовы на заведомо проигрышные запуски** в polyglot-bot: при ответе 402/401 от OpenRouter сразу выходить без повторных попыток и слать одно уведомление владельцу. | Сейчас (на 2026-10-31) бот цитат падает с `402 Payment Required` с 26.10 — баланс OpenRouter исчерпан. Wordbank будет зависеть от того же ключа. |
| П10 | **Лимит бюджета в деньгах**, а не только в количестве элементов (`LLM_DAILY_MAX_USD`), по полю `usage` в ответе OpenRouter. | Количество элементов плохо предсказывает стоимость при смене модели. |

```
│  │  └─ ipa.py               # валидация и нормализация IPA
│  ├─ lexicon/importer.py     # стриминг kaikki → lexicon.db
│  ├─ audio/                  # commons.py, tts.py (TtsProvider), resolve.py
│  ├─ telegram/               # бот захвата (polling + опционально webhook)
│  ├─ sheet_import/           # парсер CSV + сверка + отчёт
│  ├─ llm/                    # OpenRouter-клиент, practice_ipa.py
│  ├─ jobs/                   # worker: очередь задач, cron (бэкапы, prefetch, enrich)
│  └─ cli.py                  # `wordbank …` (Typer)
├─ web/                       # Svelte + Vite PWA
├─ android/                   # Kotlin, Compose
├─ tests/  (+ tests/fixtures/)
```

Стек: Python 3.13, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, pydantic-settings, Typer, httpx (а не requests, ради async), argon2-cffi, edge-tts, symspellpy, wordfreq, python-telegram-bot (v21+) или aiogram 3 (выбор агента — записать в DECISIONS), ruff, pytest, pytest-asyncio, respx (моки httpx).

Очередь задач: **без Redis/Celery**. Таблица `jobs` в `wordbank.db` + отдельный процесс `worker` с циклом опроса (одного пользователя этого хватает).

### Э0-A. Android: проверка меню выделения ⏸
**Цель:** понять, работает ли `PROCESS_TEXT` на Poco F8 Pro (HyperOS), до того как строить приложение.

**Задачи**
1. В `android/` — минимальный проект (Kotlin, Compose, minSdk 26, targetSdk — актуальный стабильный).
2. `ProcessTextActivity` с intent-filter `android.intent.action.PROCESS_TEXT`, `mimeType="text/plain"`, подпись **«Add to Wordbank»**. Полупрозрачная тема, нижняя панель (bottom sheet), показывает `EXTRA_PROCESS_TEXT` и `EXTRA_PROCESS_TEXT_READONLY`, имя вызывающего пакета (`callingPackage` / `referrer`), время от `onCreate` до первого кадра.
3. Вторая точка входа: `ACTION_SEND` `text/plain` (Share) — та же панель.
4. `.github/workflows/android.yml`: сборка debug-APK, загрузка артефакта.
5. Шаблон `docs/android-compat.md`: таблица «приложение × пункт в меню виден? × текст пришёл? × Share работает? × заметки» для Chrome, Telegram, читалки PDF/e-book, Gmail (плюс любые другие на выбор владельца).

**Приёмка:** APK собирается в CI; на эмуляторе (если доступен) пункт меню появляется в Chrome.
**⏸ Стоп:** владелец ставит APK и заполняет `android-compat.md`. Если меню не работает в важных приложениях, Share становится основным каналом (записать в DECISIONS), и Э9 планируется соответственно.

### Э2. Сервер: БД, авторизация, `/items`, Docker, бэкапы
**Задачи**
1. `db.py`: два engine. `wordbank.db` (SQLite WAL, `foreign_keys=ON`) и `lexicon.db` (открывается read-only: `?mode=ro`, `uri=true`). Путь к обоим — из `.env`.
2. Модели и миграция Alembic для личной базы: `languages` (сидинг из YAML при старте), `items` (SPEC §2.4 + `text_norm`, `lookup_count`, `capture_count`, `needs_review`, `next_due_at`, `interval_days`), `reviews`, `publications`, `events`, `audio`, `api_tokens`, `users` (одна запись), `jobs`, `sessions`.
3. `core/normalize.py`: NFC; `text_norm` = casefold + трим + схлопывание пробелов + **унификация узбекских апострофов** (U+02BB, U+2018, U+2019, U+0027, U+02BC, U+0060 → U+02BB). Оригинал хранится как есть. Юнит-тесты на каждый вариант.
4. Авторизация (SPEC §10):
   - `wordbank create-user` (CLI) → пароль Argon2id; `POST /api/v1/auth/login` → cookie `Secure; HttpOnly; SameSite=Lax`; `POST /auth/logout`.
   - `wordbank token create --scope capture,read --name android` → печатает токен один раз, в БД хранится только хэш (SHA-256). Отзыв: `wordbank token revoke`, а в Э6 — и через UI.
   - Зависимость FastAPI `require_scope("capture")`. Rate limit на `/auth/*` (простой in-memory, 5 попыток/мин).

### Э3. Импорт словаря, поиск, детекция, отчёт о покрытии ⏸
**Задачи**
1. **Импортёр** `wordbank import-lexicon --langs en,es,pt,uz --from <path|url> --out lexicon.db`:
   - потоковое чтение `raw-wiktextract-data.jsonl.gz` (gzip + построчный JSON, память < 500 МБ), фильтр по `lang_code`;
   - таблицы `lex_entries` (+ `gloss` — первая глосса первого смысла, обрезка до 120 символов; + `freq` из `wordfreq.zipf_frequency`), `lex_pron`, `lex_audio_ref`, `lex_forms` (из `form_of` / `alt_of` и из `forms` записи), `lex_translations` (только `en` → `ru`, О6), `lex_meta` (дата дампа, лицензия CC BY-SA 4.0, версия импортёра);
   - записи без произношения тоже сохраняются;
   - сборка во временный файл → `VACUUM` → атомарная замена;
   - после замены — **перепривязка** `items.entry_id` по ключу `(lang, headword, pos, ipa)`; непривязанные записываются в лог и в `docs/STATUS.md`;
   - тест на фикстуре: 30–50 строк настоящего формата wiktextract (вырезать из дампа вручную или взять примеры из документации wiktextract), включая `[…]`-фонетику, теги акцентов, аудио и form-of.
   - Подсказка исполнителю: полный импорт дампа 2.9 ГБ можно не запускать в облачной сессии, если не хватит диска или времени. Достаточно, чтобы команда работала по URL, а полный прогон делает владелец; это записать в STATUS.
2. **Поиск** `GET /lookup?q=&lang=`: точное совпадение по `headword_norm` → совпадение по `lex_forms` → вывод кандидатов по языкам. Порядок произношений — по `preferred_ipa_tags` языка. Флаг «уже сохранено» (+ `item_id`). Увеличивает `lookup_count` у сохранённого элемента. Без сетевых вызовов (тест: сеть заблокирована фикстурой).
3. **Подсказки** `GET /suggest`: префикс (индекс по `headword_norm`, `LIMIT 10`, сортировка по `freq`) + SymSpell для опечаток (расстояние ≤ 2), индекс в памяти, собирается при старте и после пересборки словаря.
4. **Детекция** `core/detect.py` строго по SPEC §5 + частотность (О8). Возвращает `[(lang, score, reason)]`. Подсказка-предпочтение (`hint`) передаётся параметром (хранится в таблице `hints` с TTL 30 мин). Тесты — все пары из SPEC §5 (`real`, `final`, `animal`, `casa`, `kitob`, `nação`) + 10 своих, для каждой записать ожидаемый результат **и причину**. Где результат неоднозначен (например, `animal` без подсказки), тест проверяет, что все нужные языки есть в кандидатах, а `lang_confidence=auto`.
5. **Нагрузочный тест** (маркер `slow`, не в CI): p95 `/lookup` < 100 мс на английском словаре полного размера.
6. **Парсер CSV таблицы** (`sheet_import/parse.py`) — только чтение и разбор по SPEC §8 (пары колонок B/C, E/F, H/I, распознавание IPA, J как определение). Сохранение — в Э7.
7. **Отчёт о покрытии** `wordbank coverage --csv words.csv` → `docs/coverage-report.md`: всего слов; доля с любой IPA; с IPA предпочитаемого варианта (UK/RP); с UK-записью в Commons; с переводом на ru; список слов без совпадения (с подсказками SymSpell).

**Приёмка:** тесты зелёные; `lexicon.db` собирается из фикстуры; `/lookup` и `/suggest` работают на фикстуре.
**⏸ Стоп:** владелец запускает полный импорт и отчёт на своём CSV (В6), смотрит отчёт. Решаем: хватает ли покрытия UK-IPA, нужен ли второй источник (например, CMUdict для американского как запасной вариант с подписью «US»).

### Э4. Аудио: Commons + edge-tts + подписи
**Задачи**

6. Скорость 0.75× делает клиент (`playbackRate`), не сервер.

**Приёмка:** тесты с моками Commons и edge-tts (успех, 429 с повтором, файл без лицензии → `licence="unknown"`, подпись всё равно есть); ни один ответ `/audio/resolve` не обходится без `label` (И5).

## 7. Сквозные требования (проверять на каждом этапе)
- Все строки — NFC; сравнение — по `text_norm` / `headword_norm`.
- Время в БД — UTC; отображение и слоты — `Asia/Tashkent`.
- Ошибки API — формат `{"error": {"code", "message"}}`, без стектрейсов наружу.
- Никаких внешних вызовов в `/lookup`, `/suggest`, `/items`, практике (И1). Тест-сторож: фикстура `no_network` (patch `socket.connect`) включена для этих тестов.
- Каждая новая переменная окружения → `.env.example`.
- Каждое решение, не описанное в ТЗ → `DECISIONS.md`.

## 8. Определение готовности v1
Все этапы Э0-A…Э12 приняты; владелец неделю пользуется захватом (Telegram + Android или Share) и практикой; бэкап восстановлен хотя бы раз на тестовой копии; в канал ушло ≥ 3 одобренных поста «Words in context».
